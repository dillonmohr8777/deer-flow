# Isolated workflow worker protocol v1

The gateway owns admission, actor/org scope, durable call IDs, budget reservations, cancellation and provider attempt receipts. Workers cannot create another queue or access provider credentials. Worker stdin/stdout uses bounded JSON Lines (one frame <= 262144 bytes); stderr is discarded and never forwarded. Launch paths are server-owned constants, never request arguments.

Model worker: the first stdin frame is `{type:"invoke",version:1,framework,call_id,worker_id,role,prompt,continuation,output_schema,model,effort,max_output_tokens,input_token_limit}`. One stdout `{type:"model_request",version:1,call_id,messages:[{role,content}]}` is permitted. The parent checks actual framework-expanded input headroom and performs exactly one native Responses call with the admitted schema/model/token ceiling, then returns `{type:"model_result",version:1,call_id,result:{output,model,effort,usage}}`. A second request fails before provider dispatch. Final stdout is `{type:"result",version:1,call_id,output}` and must equal the parent's schema-validated output. Failed/ambiguous calls never auto-retry. Workers receive only a minimal noncredential environment. Actual usage is required; unknown cost remainsnull.

Browser worker receives private `{type:"open",version:1,lease_id,deadline_ms,connect_url,session_id,api_key,ai_enabled}` and attaches only to the validated creation CDP URL of an existing owned session. The creating service owns its one-owner lease, quota, paid creation, finite deadline, release/readback, SSRF validation and evidence paths. API keys/CDP URLs remain private stdin frames and never enter model prompts or UI; this transport does not use the API key for a second session lookup. A fixed, metadata-verified pinned extension must already be included as top-level session-create `extensionId`. Read-only `Extensions.getExtensions` discovers its Chrome ID by exact enabled name/version match against the installed pinned manifest; that fixed ID enters `localBrowser.connect`. No session, Chrome process or extension is created by the worker. Pinned SDK browser close sends `Browser.close` only to this service-owned session; the creating service independently requests release and verifies exact-session terminal readback before reporting closure. Unknown creates/releases retain the owner reservation through possibleTTL. Live connections and callbacks are memory-only and cannot resume across restart. Safe error frames expose only fixed classification codes and the opaque lease ID, never raw errors/URLs/keys.

`session_id` is the explicit UUID returned by the creating service's session receipt. `connect_url` is an opaque transport credential, not an identity parser: no `sessionId` query is required and no path format is inferred. Python and worker both require exact `connect.browserbase.com` or `connect.usw2.browserbase.com`, WSS/TLS443, no userinfo or fragment, and reject a present query identity unless it occurs once and equals the receipt UUID. Wrong/blank/duplicate identities fail before child CDP transport. No additional session lookup, hostname wildcard or fallback is admitted.

Only the service-owned Stagehand mode creates `keepAlive:true` sessions, retaining the same180-second timeout and explicit release/terminal-readback ownership. Default room sessions retain false. The extension-inspection socket overlaps SDK attachment and is closed once after attachment settles; the service policy does not rely on undocumented last-connection disconnect semantics. Constant-only worker phases are `stagehand_initialization_failed`, `browser_snapshot_render_failed`, `browser_snapshot_capture_failed`, `stagehand_observation_failed`, `stagehand_extraction_failed`, `browser_cleanup_failed`; existing transport/extension/runtime/timeout classifications remain. No raw error message or URL is sent. A cleanup failure never masks a prior operation failure.

Typed browser operations are open/navigate/observe/extract/capture/close with opaque lease IDs. Navigation accepts validated snapshot text only, rendered escaped in an inert CSP-protected data document. Actual Stagehand observe/extract AI uses a customLLM relay only when gateway-admitted: stdout `{type:"model_request",version:1,lease_id,call_id,messages,output_schema}`, parent response `{type:"model_result",version:1,lease_id,call_id,result}`. Up to3deterministic lease-scoped calls are allowed, with cache disabled and actual usage validated. Real Stagehand4.1 extraction consumes two calls (extract+completion assessment), so the default runner extracts only the first of at most3snapshots within the global6-call run ceiling; all pages retain text/screenshots. No target-site JavaScript, arbitrary code, forms, login, filesystem tool or autonomous retry is exposed. Ordinary/model frames are bounded262144bytes; screenshot replies6291456bytes containing at most4194304PNGbytes.

Capability availability requires fixed installed assets and configured server access; it does not prove live useful output or installation. Offline proof executes real framework APIs with synthetic model_result frames, the complete Python browser relay, and the actual Stagehand extension in a disposable headless browser. No cloud/provider acceptance is inferred.
